# 방출 중단 중 객체 표시 보존 및 RDR 인수 항목

2026-11-13. 저출력 교육·시연 장치의 ED07 광학 중단에 적용한다.

## ECS·GUI 동작

ECS는 명시적 ED07 정지 요청 직전 객체 ID와 마지막 필터 좌표를 표시용으로 보관한다. 중단 중에는 현재 관측 좌표와 분리하고 신규 할당·실행을 허용하지 않는다. 정상 DE03의 3초 수신 만료나 PREDICTED의 1.5초 한도를 늘리지 않는다.

| 구간 | GUI v3 status | valid | 표시·동작 |
|---|---|---|---|
| 광학 중단 | 4 | 0 | 같은 ID와 마지막 좌표를 회색으로 표시, 관측 일시중지 |
| 재개 확인 후 | 5 | 0 | 재관측 대기, 같은 ID의 새 OBSERVED 필요 |
| 새 실제 관측 | 0 | 1 | 새 좌표로 정상 표시, 기존 정렬 상태는 자동 복구하지 않음 |

GUI 프레임 크기 492byte, 객체 36byte, 예약값 0은 유지한다. 4/5는 GUI 표시 코드이며 **RDR DE03 TrackState에 추가하는 값이 아니다.** 구형 GUI는 valid=0을 숨기므로 함께 갱신해야 한다. GUI는 대기 행과 선택을 유지하며 할당 버튼을 비활성화한다. 순차 목록은 정확히 같은 ID의 재관측을 최대 13초 기다리고, 기한 초과·소실 시 기존 오류 처리로 종료한다. 다른 ID를 자동 대입하지 않는다.

현재 상수는 `ObservationRetention::pause_limit_s=10`, `reacquire_limit_s=3`이다. 각각 정지 요청과 재개 완료 확인을 기준으로 단조 시계로 계산한다. 중단이 길면 표시를 제거하되 광원을 시간만으로 재개하지 않는다. 새 실제 관측 전에는 예측값만으로 유효성을 복원하지 않는다. 연결·세션·감시·보고·RDR 설치 위치가 바뀌면 보관을 초기화한다. 제외된 ID도 제거한다.

정상 제어 데이터와 별개인 최대 10개의 표시 캐시다. 재획득 대기 ID를 우선 표시하므로 기존 10개가 모두 대기 중이면 새 ID는 기존 표시 기한이 끝난 뒤 보일 수 있다. 수신기는 10개 슬롯이 찼을 때 새 OBSERVED에 한해 가장 오래된 소실·만료 슬롯을 재사용한다. 현재 유효한 관측과 제외된 슬롯은 밀어내지 않는다.

## RDR 담당자 수정 요청

1. ED07=0에서 추적 테이블·ID 할당기를 초기화하지 않는다. ID, 마지막 실제 관측 시각·위치·속도·관측 특징을 별도 보관한다. 중단 중 미검출 횟수를 일반 소실 삭제 조건에 그대로 적용하지 않는다.
2. 중단 10초 미만인 경우 재개 후 최대 3초 동안 새 실제 관측을 기존 추적과 일대일 대응시킨다. 확실한 대응에만 기존 ID를 유지한다. 교차·복수 후보·불확실한 움직임에서는 새 ID를 부여한다. 이 저장소는 RDR의 대응 알고리즘을 구현하지 않는다.
3. ED07 중복 요청은 최초 중단 시각과 기한을 연장하지 않는다. 중단 10초 이상·재획득 3초 초과이면 동일성 보관을 폐기한다. 폐기된 ID를 같은 세션의 다른 객체에 재사용하지 않는다.
4. 정지 전 센서·송신 버퍼를 폐기한다. DE07 재개 OK 후 새 취득 결과에만 OBSERVED=1/Detected=1을 붙여 송신한다. PREDICTED는 재획득 확인을 대체하지 않는다. 기존 32byte DE03, 원본 XYZ·관측 PAN/TILT·TrackState 계약을 유지한다.
5. 대기 중 LOST 또는 송신 공백이 발생해도 보관 추적과 구분한다. ED06 명시적 정지·보고 중지·새 세션·재부팅은 연속성 유지 대상에서 제외한다. ED04 제외도 존중한다.
6. 아래 장치 인수 시험으로 구현과 실제 센서 동작을 확인한다.

## 검증과 적용 범위

- C++ 단위 시험: 중단/재획득 상태, 정상 데이터 만료 후 표시, 오래된 관측·예측 거절, 동일/다른 ID, 기한 만료, 세션·연결·위치·감시 변경 초기화, IPC valid 조합, 포화 슬롯 재사용 및 유효 관측 보호.
- UDP/GUI IPC 통합 시험: GUI 구동 후 10개 객체 관측 → EF04/ED07 중단 → 3초 이상 행 유지·할당 거절 → OFF/재개 → 대기 → 동일 ID 복원. 새 ID가 들어오는 경우 기존 ID로 치환하지 않고 이전 표시를 만료한다.
- GUI WPF 시험: 실제 ApplyFrame에서 행 인스턴스 보존, 대기 상태 문구·할당/실행 차단, 정상 재관측 복원, 새 ID 구분, 일반 소실 제거. `dotnet run --project tests/ObservationRetention.csproj -c Release`로 실행한다.
- RDR 장치 인수 시험: 정지 객체·다중 객체·교차·대체 객체·시간 초과·재연결·재부팅·중복 ED07·지연 프레임을 실제 센서로 확인해야 한다. 이 작업의 로컬 시험은 localhost 모의 장치로 수행한다.

DE03에는 취득 시각·중단 세대가 없어 ECS가 재개 이후에 도착한 과거 프레임을 완전히 판별할 수 없다. RDR의 버퍼 폐기와 순번·새 관측 관리가 필수다. RDR이 여전히 새 ID를 부여한다면 화면 대기는 개선돼도 동일 ID 복원은 완료되지 않는다.

## 경계 조건 보완

RDR 설치 위치 변경은 표시 좌표 보관만 지운다. 방출 억제와 재개 이후 새 관측 대기 조건은 유지한다. 이미 재개 후 실제 관측이 확인된 객체의 일반적인 위치 편집은 기존처럼 좌표를 다시 계산한다. 표시 캐시가 비어 있거나 초기화됐다는 이유로 억제 중 데이터를 유효하게 만들지 않는다.

보관 만료 후 일반 LOST 레코드도 IPC에 전달한다. GUI는 `valid=0`인 일반 소실 객체를 숨기며, 상태 4/5인 경우에만 대기 표시를 유지한다. 보관 만료를 이유로 소실 상태 전달까지 생략하지 않는다.

광학 중단으로 끊긴 기존 할당은 같은 ID가 재관측돼도 `alignment_required`로 실패 상태를 유지한다. 명시적 Assign 또는 Cancel 후 Assign으로 다시 정렬해야 한다. 단순한 짧은 수신 공백의 기존 복구 동작은 유지한다. 실제 시연 종료 판정은 FCS 종료 상태로 처리하며 할당 복원 여부와 분리한다.

`test_retention_regressions.py`는 GUI 위치 편집 중 차단 유지, CLI 출력 후 재할당, GUI 시연 후 재할당을 실제 UDP/IPC 모의 경로에서 검증한다.
