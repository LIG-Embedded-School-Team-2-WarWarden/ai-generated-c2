# GUI 배치 촬영 연동

기준 GUI: [main 37d7ab9](https://github.com/LIG-Embedded-School-Team-2-WarWarden/c2-GUI/commit/37d7ab9e58369b20230b5fb19815fb5f45a8bd83), PR #21·#22.
EF05는 촬영 시작, 레이저는 촬영 대상 표시용이다. Aim/Fire/Hit는 기존 GUI/API 식별자이며 장치 명령을 새로 정의하지 않는다.
Named Pipe v3 요청/응답 40바이트와 SharedMemory v3 492바이트를 유지한다.

## 명령 계약

모든 명령은 GUI 파이프에서 `requestId != 0`, `rdrId = fcsId = 1`을 요구한다.
대상 ID는 1~65535이며 기능 조회만 ID 0을 허용한다. 등록은 최대 10개다.

| 명령 | 처리 |
|---|---|
| 1200 GetBatchStatus | ID 0: 지원 여부 조회. 다른 ID: 해당 행의 상태. 미등록이면 Idle(0) |
| 1201 RegisterBatchTarget | 최신 실제 관측 객체를 등록하고 Confirmed(102) 반환. 지향·촬영 없음 |
| 1202 CancelBatchTarget | 해당 행만 해제. 진행 중 지향·촬영·재개·결과 관측은 StatusPending. 마지막 행 또는 사용 중 슬롯 해제는 FCS OFF 수락 확인 필요 |
| 1203 AimBatchTarget | 공통 정지가 완료된 배치의 고정 관측값으로 EF03. 실제 정렬 확인 후 110 → 104 |
| 1204 PauseBatchScan | 등록된 모든 미촬영 객체의 최신 관측값을 보관하고 ED07=0을 한 번 요청. 실제 정지 확인까지 지향·촬영 금지 |
| 1205 FireBatchTarget | 선택된 객체에 기존 EF05 촬영 요청. 105 → 최신 FE02 동작 관측 및 종료 확인 후 106 |
| 1206 ResumeBatchScan | FCS 동작 종료 확인 후 ED07=1을 한 번 요청. 촬영 완료 행들은 재개 확인 후 107로 전환해 각각 결과 관측 |
| 1207 RetryBatchTarget | 111 상태에서 같은 ID의 최신 관측을 확인하고 102로 재등록 |
| 1208 StopBatchCapture | 진행 중인 행의 할당을 보존하고 기존 EF04 OFF로 남은 각도 스캔을 중단. 112 → 최신 FE02에서 출력 OFF 및 복귀 완료가 확인되면 106 |

응답 `assignedTargetId`는 조회/요청한 ID다. `assignmentState`는 그 행의 상태이며,
`fireState`(ECS 내부 `active`)는 모든 행에 공통인 다음 비트다.

| 비트 | 의미 |
|---|---|
| 1 | 공통 라이다 정지 확인 완료 |
| 2 | 조사 재개 가능 |
| 4 | 다음 객체 지향 슬롯 사용 가능 |
| 8 | FCS의 최신 정상·동작 종료 상태 확인 |

명령 Success는 접수이며 장치 동작 완료가 아니다. GUI가 실패 행도 표시할 수 있도록 1200 조회 자체는 Success를 반환한다.
실패 행의 상태는 3이며 내부 상세 사유는 `BATCH ... reason=...` 로그에 남긴다. 현재 GUI 배치 응답은 상세 사유와 완료 단계를 별도로 운반하지 않는다.
연결 여부는 `isConnected`로 별도 전달한다. 기존 단일 수행이 남아 있을 때 ID 0 조회는 NotSupported를 반환하여 GUI가 1010/0 조회로 기존 수행을 마칠 수 있게 한다.

## 관측값과 장치 소유권

- 정지 요청 시 모든 미촬영 등록 객체를 다시 검증한다. 누락·제외·예측 전용·3초 초과 관측은 거절하고 STOP을 보내지 않는다.
- 제어 좌표는 정지 직전의 필터 좌표에서 보관한다. 화면 표시용 보존 캐시와는 별도이며 중지 중 신규 등록은 금지한다. 고정 장면을 전제로 한 배치다.
- RDR 세션 변경, 공통 정지 상태 상실, 정지 완료 후 RDR 자세 변경, FCS 상태 만료·오류, 설치 위치·보정 변경은 진행 중인 배치를 실패 처리하고 FCS OFF를 요청한다.
- 정지 후 자세 비교는 STOP 완료 당시 값을 고정 기준으로 사용한다. PAN/TILT 각 축의 ±0.1°(장치 보고값 1단위) 변동은 허용하고, 기준에서 이를 초과하면 중단한다. PAN은 0°/360° 경계를 순환 비교하며, 각도 무효값(-32768)은 정지 완료 시점부터 거절한다. 매 표본으로 기준을 갱신하지 않아 누적 이동을 숨기지 않는다. 2026-11-16의 TILT 100.2°→100.3° 변화로 배치 전체가 실패한 사례를 회귀 테스트에 포함했다.
- 한 번에 한 객체만 FCS 지향·촬영 슬롯을 쓴다. 완료된 행은 보존하면서 다음 객체를 처리한다. 다른 행을 해제해도 진행 중인 촬영은 끊지 않는다.
- 정지 완료에는 기존 온도 7/8 경고 정책을 포함한 `stop_completed()`를 사용한다. ED07 처리 제한은 65초이며 응답 수락만으로 정지 완료를 표시하지 않는다.
- 객체별 정렬 완료 후 촬영 입력은 시간 제한 없이 오퍼레이터가 요청할 때까지 대기한다. 대기 중에도 연결·상태 최신성·정렬·장치 오류 검사는 유지하며, 촬영 시작 후 완료 대기는 30초다.
- 재개는 운용자 요청으로만 수행한다. 미촬영 객체를 남겨 두고 재개할 수 있으며, 다음 정지 시 새 관측을 다시 확보해야 한다. 마지막 행 취소 후에는 기존 OFF 확인 기반 광학 복구를 사용한다.
- 배치 소유 중 기존 단일 제어, 독립 지향·출력, 설치/보정 변경, RDR 변경 명령은 차단한다. 조회와 명시적 CLI OFF는 허용한다. 배치 해제는 GUI의 1202를 사용한다.
- 결과 관측은 기존 `ManualSequence`의 현행 카메라 결과 규칙을 재사용한다. 106은 장치 동작 종료이며 사진 파일 저장·촬영 품질을 보증하지 않는다.
- 3초 미검출은 HIT 대신 상태 3 / `result_unconfirmed`를 기록한다. 배치가 idle로 돌아간 뒤에도 재관측 시작부터 총 13초까지 늦은 관측으로 111 갱신을 허용한다. 다른 ID는 15cm 내 단일 후보의 서로 다른 두 관측이 필요하며, ID·제어 할당은 변경하지 않는다. 현재 배치 GUI는 상태 3의 상세 사유를 별도로 받지 못하므로 `result_unconfirmed`는 ECS 로그로 구분한다.
- GUI 재연결 시 객체별 1200 조회로 복원한다. ECS 재시작 시 저장된 제어를 자동 재개하지 않는다.

## 검증 범위

`C2.Tests/Sources/batch_sequence.cpp`는 장치 프로세스나 소켓 없이 메모리의 상태와 명령 기록으로 배치 전이 및 실패 경로를 검사한다.
동일 FCS에 여러 객체 등록, 단일 정지/재개, 순차 촬영, 중복 요청, 다른 행 취소, 관측 만료·세션 변경·온도 오류·응답 실패 및 40바이트 응답 플래그를 포함한다.
실제 FCS와 `fcs_dummy.py` 실행 및 실장비 인수 시험은 별도다.
`C2.Tests/Integration/test_batch_disconnected.py`는 FCS를 비활성화한 ECS와 격리된 Named Pipe에서 기능 조회, 잘못된 ID·버전·파이프 거절 및 미연결 응답을 검사한다. RDR 주소도 응답하지 않는 임시 loopback 포트로 제한한다.
