# GUI 수동 시퀀스 연동 — 2026-11-14

기준 GUI: c2-GUI main 030c3b0. ECS 변경 전: cd1e474.
카메라 프로젝트: EF05는 촬영 시작, 레이저는 촬영 중인 객체 표시용이다. Aim/Fire/Hit는 기존 GUI/API 식별자를 유지한 것이다. FE02 동작 종료는 사진 파일 저장이나 촬영 품질의 검증이 아니다.
RDR/FCS 신규 UDP 명령이나 바이트 배치 변경은 없다. Named Pipe v3 요청/응답 40byte, SharedMemory v3 492byte를 유지한다.

## 명령 및 완료 상태

| GUI 명령 | 의미 | ECS 상태 |
|---|---|---|
| 1001 RegisterManualTarget | 최신 관측 대상 등록. 모터 동작 없음 | 102 Confirmed |
| 1003 StartManualAim | 기존 EF03 지향 | 110 ManualAiming → 실제 정렬 확인 후 103 Aimed |
| 1004 PauseManualScan | 기존 ED07=0 | 처리 중 103 유지 → 실제 OFF 확인 후 104 ScanPaused |
| 1005 StartManualFire | 기존 EF05 촬영 시작 | 105 Firing → FE02 장치 동작 종료 확인 후 106 FireConfirmed |
| 1007 ResumeManualScan | 기존 ED07=1 | 처리 중 106 유지 → 실제 ON 확인 후 107 ScanResumed |
| 1009 RetryManualAssignment | 111에서 최신 관측을 확인하고 재등록 | 102 Confirmed |
| 0 GetStatus | ECS가 가진 현재 단계 조회 | targetId, assignmentState, fireState |
| 2 CancelAssignment | 기존 EF04 OFF 적용 확인 후 수행 해제 | 0 Idle; 광학 복구는 별도 최신 상태 확인 후 진행 |

1002/1006/1008은 GUI 열거형에만 존재하며 미지원(5). 101 Detected는 예약/미사용이다. 108 ResultConfirmed는 별도 확인된 결과에만 사용하고, 111 TargetStillPresent는 재개 후 동일 ID의 새 OBSERVED를 확인한 상태이다. 3 Failed는 장치 오류 및 결과 미확정에 대한 현재 GUI 호환 상태이다. 명령 결과 Success=0은 접수이며 완료가 아니다. GetStatus는 기존 GUI 호환상 result=0일 수 있으므로 assignmentState를 확인한다.

GUI는 1001에 대해 102를 기대한다. 101을 반환하면 조준 버튼이 진행되지 않는다. 110→103, 105→106, 107→결과 전이는 ECS에서 수행한다. 조준 확인은 EF03 수락 이후의 최신 FE02, 모터 정지 및 기존 정렬 허용 조건으로 판단한다. FE05 수락만으로 완료하지 않는다.

## 소유권과 동작 제한

- ECS가 한 대상의 전체 수행을 소유한다. 완료/실패 후에도 해제 전에는 다른 대상 등록을 거절한다.
- 진행 중 기존 할당/실행, 설치 위치 변경, 장비 설정 변경, RDR 구동 명령과 독립 CLI 지향/출력/센서 제어를 차단한다. 조회와 OFF/취소는 허용한다.
- 같은 단계의 중복 등록·조준·중지·발사·재개 요청은 동작을 반복하지 않는다. 다른 대상 ID, 순서 건너뛰기, 잘못된 장치 ID는 거절한다.
- 표시용 마지막 좌표로 신규 수행을 시작하지 않는다. 중지 전에 실제 조준을 마친 동일 수행만 고정 대상 시연을 계속할 수 있다. 세션 변경·상태 만료·자세 변경·중단 한도 초과이면 무효화한다.
- 수동 모드에서는 정상 동작 종료만으로 라이다를 자동 재개하지 않고 1007을 기다린다. 취소 후에는 기존 OFF 확인 기반 복구를 사용한다.
- 중단 상한은 기존 ICD의 10초이며 발사 전 조작 대기도 포함한다. 결과 관측은 실제 재개 확인 후 3초를 사용한다. 중단 초과는 자동 재개 근거가 아니다.
- 장치 오류·통신 단절·동작 종료 미확인에서는 성공을 합성하지 않고 OFF를 요청한다. 실패한 OFF 요청의 기존 재시도는 유지한다. 원인 확인 후 GUI 취소로 수행을 해제한다.
- GUI 재연결 시 GetStatus로 현재 수행을 복원한다. ECS 프로세스 재기동은 이전 수행을 자동 재개하지 않는다.

## RDR v15 적용

ED07 내부 SDK 처리 5초 + 통신 여유 1초 = ECS 요청 만료 6초. DE07 OK는 SDK 명령 완료이며 bit4=0인 정상 응답도 수신한다. 실제 OFF 판단은 DE07 정지 OK와 bit3=1/bit4=1/bit5=0/bit6=1을 별도로 요구한다. 재개 단계 역시 실제 ON을 확인한 뒤 완료로 표시한다. SDK 준비는 unknown emission 때문에 시작 자체를 거절하지 않으나, 광학 확인이 되지 않으면 GUI 구동 완료/출력 허가는 주지 않는다.

RDR의 ID 보존, 버퍼 폐기와 실제 새 관측 송신은 기존 장비 ICD 계약이다. ECS에서 새 ID를 이전 ID로 치환하지 않는다. DE03에 취득 시각/세대가 없어 지연 패킷을 완전히 구분할 수 없는 한계는 유지되며 실장비 인수가 필요하다.

## 결과 판정 및 운용자 확인

기존 DE03은 명중 메시지가 아니다. 같은 ID의 새 OBSERVED는 111로 처리한다. 보고 공백·LOST·새 ID·연결 장애를 108/HIT로 바꾸지 않는다. 3초 안에 결과 근거가 없으면 3 Failed와 로그의 결과 미확정 사유를 남긴다. GUI에 판정 불가 전용 상태가 없어 기존 실패 표시를 사용한다.

운용자가 촬영 결과를 별도로 확인한 경우에만 ECS 콘솔에서 다음 기존 명칭의 명령으로 결과 확인을 기록할 수 있다. 객체 소실이나 장치 종료만으로 촬영 성공을 추론하지 않는다.

```text
sequence confirm-hit TARGET_ID
```

이것은 새 장비 명령이나 센서 자동 판정이 아닌 명시적 수동 결과 기록이다. 실제 재개를 확인한 동일 수행의 결과 대기 또는 결과 미확정 상태에서만 허용한다. 대상 ID, RDR 세션, 실제 조사 상태 및 최신 FCS OFF/무오류 상태를 다시 확인한다. 이벤트 로그에 `source=console_visual_confirmation`을 기록하고 상태 108을 GUI에 전달한다. 같은 ID의 재관측으로 이미 111이 된 경우에는 성공 확인을 허용하지 않는다. 현재 GUI의 결과 확인 명령 1008은 계속 미지원이다.

현재 GUI의 108 문구는 HIT이고 센서 판정/수동 확인을 별도 표시하지 못한다. 원인은 ECS 이벤트 로그로 구분한다. 판정 불가와 수동 확인을 GUI에 직접 표시하는 기능은 향후 GUI 확장 사항이다.
