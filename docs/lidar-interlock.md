# 저출력 시연 레이저와 라이다 방출 연동

ECS의 `fcs laser on`(EF04) 및 GUI 시연(EF05)은 RDR의 실제 라이다 방출 정지를 확인한 뒤에만 전송한다. FCS 1대인 비무장 교육·시연 장치 기준이다.

## 장치 적용 조건

- RDR 펌웨어에 ED07/DE07 및 상태 비트 3–6을 구현해야 한다. 미지원 장치에서는 ECS가 출력을 차단한다.
- SDK 취득 중지·UDP 보고 중지가 실제 광원 OFF인지 별도로 확인해야 한다. 실제 방출 상태 확인이 불가능하면 완료로 응답하지 않는다.
- FCS는 모터 구동·시연 중에도 EF04 OFF를 처리하고, 시연을 종료하여 출력이 다시 켜지지 않게 해야 한다. FCS 펌웨어는 이 저장소 변경 범위 밖이다.
- 2초의 정지·재개 대기 한도는 현재 ECS 설정이며 장치의 성능 보장치가 아니다. 실제 장비에서 측정해야 한다.

## RDR 메시지

기존 24byte Big-endian 제어 메시지를 사용한다. ED07=0xED07, DE07=0xDE07이다.

| 오프셋 | 크기 | ED07 | DE07 |
| --- | --- | --- | --- |
| 0 | 2 | 메시지 ID | 메시지 ID |
| 2 | 2 | TxSeq | TxSeq |
| 4 | 2 | 0 | 대응 요청 TxSeq |
| 6 | 2 | 0 정지·억제 설정, 1 재개·억제 해제 | 요청값 복사 |
| 8 | 2 | 예약 0 | 0 |
| 10 | 4 | 세션 ID | 요청 세션 ID |
| 14 | 2 | 예약 0 | 기존 RDR 처리 결과 |
| 16 | 2 | 예약 0 | 현재 고각 |
| 18 | 2 | 예약 0 | 현재 방위각 |
| 20 | 2 | 예약 0 | 상태 플래그 |
| 22 | 2 | 예약 0 | 패딩 0 |

모든 RDR 제어 응답의 상태 플래그에 bit 3=방출 제어 지원, bit 4=실제 방출 상태 유효, bit 5=실제 방출 ON, bit 6=방출 억제 중을 추가한다. bit 7은 예약한다. 기존 bit 0–2와 운용 모드는 유지한다.

정지 완료는 DE07 OK와 지원·상태 유효·OFF·억제 중을 함께 확인해야 한다. PENDING 또는 DE02만으로 완료하지 않는다. 재전송은 동일 패킷을 사용한다. RDR은 PENDING 캐시를 최종 결과로 갱신한다. 캐시된 최종 응답이 최신 DE02보다 오래된 경우 ECS는 최신 상태를 되돌리지 않고, 현재 상태가 완료 내용과 일치할 때만 완료를 수락한다.

ED07은 모터·감시 모드·보고 설정을 바꾸지 않는다. 억제 중 ED06 시작이나 재연결이 발생해도 방출하지 않는다. 재개는 ACTIVE에서만 실제 ON으로 전환하며 IDLE에서는 OFF를 유지한다. 억제는 연결 만료·새 세션에서 유지한다. 장치 재부팅으로 상태가 소실되면 억제하여 기동한다.

## 종료 및 복구

출력 명령 이후 최신 FE02에서 ON 또는 시연 중을 관측하고 이후 OFF·시연 종료를 확인하면 라이다를 재개한다. 또는 명시적 EF04 OFF의 성공·현재 OFF 응답 이후 새 FE02에서 OFF·시연 종료를 확인한다. 단순 시간 경과는 종료 근거가 아니다.

CLI ON은 기존과 같이 1초 뒤 OFF를 요청한다. CLI·GUI의 수동 OFF를 포함하여 BUSY·무응답·장치 오류·현재 ON 응답 또는 송신 예외에서는 1초 간격으로 재시도한다. 수락 및 현재 OFF를 함께 확인해야 재시도를 해제하며, 라이다는 이후 최신 상태에서 종료를 확인하기 전까지 억제를 유지한다. EF05 완료를 관측하지 못했거나 상태가 불확실하면 `fcs laser off`로 명시적으로 복구한다. 재연결 후에도 명시적인 OFF 확인이 필요하다.

ED07의 통신 요청도 상위 인터록과 같은 2초 한도로 만료한다. 만료된 요청은 재전송을 중단하고 늦은 완료 응답을 무시한다. RDR 상태 확인 통신은 계속하며, 명시적 FCS OFF와 최신 종료 상태를 확인하면 새 Sequence의 ED07 재개 요청을 보낼 수 있다. 이 로컬 만료는 이미 전송된 요청을 장치에서 취소했다는 의미는 아니다.

실제 정지 동안 관측 데이터가 끊기므로 대상 소실·재획득이 발생할 수 있다. 모의 장치도 억제 중 새 관측을 생성하지 않는다. 프로세스 종료 시에는 기존 감시 정지·FCS OFF 절차를 수행하고 라이다를 자동 재개하지 않는다.

## 억제 기동과 GUI 복구

RDR이 억제 상태로 기동한 경우, 할당·시연이 없는 초기 상태에서 GUI 구동을 요청하면 ECS가 FCS OFF 확인도 시작합니다. EF04 OFF 수락·현재 OFF와 이후 최신 FE02의 OFF·시연 종료를 확인하고, 진행 중인 RDR 명령이 완료된 뒤 ED07 재개를 요청합니다. FCS 확인이 불가능하면 억제를 유지합니다.

GUI Cancel(명령 2)은 대상 할당이 없어도 OFF 및 억제 복구에 사용할 수 있습니다. OFF 수락인데 현재 ON이면 성공으로 표시하지 않으며 재시도합니다. Cancel만으로 감시를 시작하지 않습니다. 기존 할당·출력 진행 중에는 구동 버튼이 초기 OFF 절차를 덮어쓰지 않습니다.

RDR 펌웨어는 억제 중에도 DE06으로 ACTIVE 진입을 완료할 수 있어야 합니다. 새 광학 프레임을 DE06 완료 필수 조건으로 요구하면 ED07 재개와 상호 대기하므로, 억제 중에는 SDK 준비·최신 모터 위치 등으로 시작을 확인하고 실제 취득은 ED07 재개 이후 시작합니다. GUI 구동 명령의 Success는 접수 의미입니다. 아래 GUI 구동 순서의 최신 구현은 DE07 재개 확인 후 isOperating을 활성화합니다.

## 실행 차단 진단 (2026-11-13)

GUI 실행 응답에 아래 결과 코드를 추가했다. IPC v3의 40바이트 크기는 유지하며, ECS와 `projects/c2-GUI`를 함께 업데이트해야 한다. 이전 GUI는 신규 코드를 알 수 없는 응답으로 표시할 수 있다. 기존 7–14 결과의 호환 변환은 유지한다.

| 코드 | 의미 |
| --- | --- |
| 15 | RDR 방출 제어 미지원: ED07/DE07 지원 펌웨어 확인 |
| 16 | RDR 실제 방출 상태 미확인 |
| 17 | 연동 진행 중 또는 억제/오류 복구 필요 |
| 18 | 라이다 정지 및 최종 FCS 준비 확인 실패 |
| 19 | RDR 연결 끊김 |
| 20 | RDR 이전 명령 처리 중 |

진입 차단 시 events.log에 정확한 사유와 supported, known, inhibited, last_result, phase를 기록한다. 18은 정지 응답 실패뿐 아니라 정지 이후 FCS 상태 재확인 실패도 포함한다. 차단 시 EF05는 전송하지 않는다. 지원 비트가 없다는 사실만으로 장비의 실제 펌웨어 버전을 판별하지는 않는다.

구버전 RDR 모의 테스트는 GUI 명령 3이 결과 15를 받고 FCS 출력 요청은 전송하지 않는 것까지 검증한다. 이는 실제 장비의 펌웨어 교체나 광학 출력 검증을 대신하지 않는다.

## GUI 구동 순서 (2026-11-13)

GUI 명령 6의 시작 요청은 다음 비동기 절차를 실행한다.

1. FCS EF04 OFF 성공·현재 OFF 응답을 받고, 그 이후 최신 FE02에서 연결·이동/시연/출력 종료·무오류를 확인한다(최대 10초).
2. 보고가 꺼져 있으면 ED03 보고를 켠 후 ED06 시작을 요청하고 준비 완료를 기다린다(최대 45초).
3. 최신 FCS OFF 상태를 다시 확인하고 ED07=1을 전송한다. 기존 억제 여부와 무관하게 매 시작 요청마다 전송한다.
4. DE07 완료와 지원·상태 유효·ACTIVE·실제 방출 ON·억제 해제를 확인한 뒤 공유 메모리 isOperating을 활성화한다(재개 최대 2초).

명령 6 성공은 접수 의미이며 GUI는 명령 18로 완료를 조회한다. 결과 7은 진행 중, 0은 완료, 21은 준비 완료 후 방출 재개 확인 실패, 22는 FCS OFF 확인 실패, 23은 RDR 준비 실패다. 실패 시 isOperating은 비활성으로 유지되고 실패 사유를 표시한다. 정지 요청은 진행 중 시작 절차를 취소한다. RDR 펌웨어는 억제 상태에서도 ED06 준비 완료 응답을 보낼 수 있어야 한다.

이 절차는 GUI 구동 명령 6에 적용한다. 저수준 CLI `rdr start` 및 RDR 제어 파이프 명령 11은 기존 ED06 진단 명령으로 유지한다.

## 실물 RDR + 로컬 FCS 더미

- 시작: `powershell -File scripts/start-rdr-live-fcs-dummy.ps1`
- 종료: `powershell -File scripts/stop-rdr-live-fcs-dummy.ps1` (GUI는 별도 종료)
- FCS 더미: `simulators/fcs_dummy.py`, UDP `127.0.0.1:22000`. EF01~EF05, 0.1도 각도, 방위각 45~315도/고각 -30~90도, OFF 취소, 상태 플래그와 중복 응답을 모사한다. GPIO/UART 및 물리 출력은 없다. 실제 스캔 궤적·모터 보정은 재현하지 않는다.
- 설정: `configs/rdr-live-fcs-dummy.json`. 첫 실행에 현재 `rdr-live.json`의 설치/영점/거리/시야각을 복사하고 FCS 주소만 로컬로 변경한다. 이후 더미 환경에서 저장한 설정은 이 별도 파일에 유지한다. 실장비 설정 파일은 수정하지 않는다.
- 로그/상태: `logs/rdr-live-fcs-dummy/`. 시작 스크립트는 기존 ECS가 실행 중이면 중복 실행을 거부한다.
