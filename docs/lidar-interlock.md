# 저출력 시연 레이저와 라이다 방출 연동

ECS의 `fcs laser on`(EF04) 및 GUI 시연(EF05)은 RDR 중지 완료 조건을 확인한 뒤 전송한다. 일반 상태는 실제 OFF 확인을 요구하며, 아래 온도 경고 정책은 새 STOP 명령 완료를 근거로 진행한다. FCS 1대인 비무장 교육·시연 장치 기준이다.

## 장치 적용 조건

- RDR 펌웨어에 ED07/DE07 및 상태 비트 3–6을 구현해야 한다. 미지원 장치에서는 ECS가 출력을 차단한다.
- SDK 취득 중지·UDP 보고 중지가 실제 광원 OFF인지 별도로 확인해야 한다. SDK 제어 완료와 실제 방출 상태 확인을 구분한다. 온도 상태 7·8을 제외한 실제 OFF 미확인 상태에서는 FCS 출력을 허용하지 않는다.
- FCS는 모터 구동·시연 중에도 EF04 OFF를 처리하고, 시연을 종료하여 출력이 다시 켜지지 않게 해야 한다. FCS 펌웨어는 이 저장소 변경 범위 밖이다.
- 6초의 정지·재개 대기 한도는 현재 ECS 설정이며 장치의 성능 보장치가 아니다. 실제 장비에서 측정해야 한다.

## RDR 메시지

기존 24byte Big-endian 제어 메시지를 사용한다. ED07=0xED07, DE07=0xDE07이다.

| 오프셋 | 크기 | ED07 | DE07 |
| --- | --- | --- | --- |
| 0 | 2 | 메시지 ID | 메시지 ID |
| 2 | 2 | TxSeq | TxSeq |
| 4 | 2 | 0 | 대응 요청 TxSeq |
| 6 | 2 | 0 정지·억제 설정, 1 재개·억제 해제 | 요청값 복사 |
| 8 | 2 | 예약 0 | 0 |
| 10 | 4 | 세션 ID | 요청 세션 ID |
| 14 | 2 | 예약 0 | 기존 RDR 처리 결과 |
| 16 | 2 | 예약 0 | 현재 고각 |
| 18 | 2 | 예약 0 | 현재 방위각 |
| 20 | 2 | 예약 0 | 상태 플래그 |
| 22 | 2 | 예약 0 | 패딩 0 |

모든 RDR 제어 응답의 상태 플래그에 bit 3=방출 제어 지원, bit 4=실제 방출 상태 유효, bit 5=실제 방출 ON, bit 6=방출 억제 중을 추가한다. bit 7은 고온 보호 정지 래치이다. 기존 bit 0–2와 운용 모드는 유지한다.

정지 완료는 DE07 OK와 지원·억제를 확인하고, 일반 상태에서는 유효·OFF까지 확인한다. 신선한 상태 7·8에서는 아래 명령 완료 정책을 적용한다. PENDING 또는 DE02만으로 완료하지 않는다. 재전송은 동일 패킷을 사용한다. RDR은 PENDING 캐시를 최종 결과로 갱신한다. 캐시된 최종 응답이 최신 DE02보다 오래된 경우 ECS는 최신 상태를 되돌리지 않고, 현재 상태가 완료 내용과 일치할 때만 완료를 수락한다.

ED07은 모터·감시 모드·보고 설정을 바꾸지 않는다. 억제 중 ED06 시작이나 재연결이 발생해도 방출하지 않는다. 재개는 ACTIVE에서만 실제 ON으로 전환하며 IDLE에서는 OFF를 유지한다. 억제는 연결 만료·새 세션에서 유지한다. 장치 재부팅으로 상태가 소실되면 억제하여 기동한다.

## 종료 및 복구

출력 명령 이후 최신 FE02에서 ON 또는 시연 중을 관측하고 이후 OFF·시연 종료를 확인하면 라이다를 재개한다. 또는 명시적 EF04 OFF의 성공·현재 OFF 응답 이후 새 FE02에서 OFF·시연 종료를 확인한다. 단순 시간 경과는 종료 근거가 아니다.

CLI ON은 기존과 같이 1초 뒤 OFF를 요청한다. CLI·GUI의 수동 OFF를 포함하여 BUSY·무응답·장치 오류·현재 ON 응답 또는 송신 예외에서는 1초 간격으로 재시도한다. 수락 및 현재 OFF를 함께 확인해야 재시도를 해제하며, 라이다는 이후 최신 상태에서 종료를 확인하기 전까지 억제를 유지한다. EF05 완료를 관측하지 못했거나 상태가 불확실하면 `fcs laser off`로 명시적으로 복구한다. 재연결 후에도 명시적인 OFF 확인이 필요하다.

ED07의 통신 요청도 상위 인터록과 같은 6초 한도로 만료한다. 만료된 요청은 재전송을 중단하고 늦은 완료 응답을 무시한다. RDR 상태 확인 통신은 계속하며, 명시적 FCS OFF와 최신 종료 상태를 확인하면 새 Sequence의 ED07 재개 요청을 보낼 수 있다. 이 로컬 만료는 이미 전송된 요청을 장치에서 취소했다는 의미는 아니다.

실제 정지 동안 관측 데이터가 끊기므로 대상 소실·재획득이 발생할 수 있다. 모의 장치도 억제 중 새 관측을 생성하지 않는다. 프로세스 종료 시에는 기존 감시 정지·FCS OFF 절차를 수행하고 라이다를 자동 재개하지 않는다.

## 억제 기동과 GUI 복구

RDR이 억제 상태로 기동한 경우, 할당·시연이 없는 초기 상태에서 GUI 구동을 요청하면 연결된 FCS에 대해 ECS가 OFF 확인도 시작합니다. EF04 OFF 수락·현재 OFF와 이후 최신 FE02의 OFF·시연 종료를 확인하고, 진행 중인 RDR 명령이 완료된 뒤 ED07 재개를 요청합니다. 연결된 FCS의 OFF 확인이 불가능하면 억제를 유지합니다. FCS가 미연결이면 GUI 구동 과정의 FCS 확인을 생략합니다.

GUI Cancel(명령 2)은 대상 할당이 없어도 OFF 및 억제 복구에 사용할 수 있습니다. OFF 수락인데 현재 ON이면 성공으로 표시하지 않으며 재시도합니다. Cancel만으로 감시를 시작하지 않습니다. 기존 할당·출력 진행 중에는 구동 버튼이 초기 OFF 절차를 덮어쓰지 않습니다.

RDR 펌웨어는 억제 중에도 DE06으로 ACTIVE 진입을 완료할 수 있어야 합니다. 새 광학 프레임을 DE06 완료 필수 조건으로 요구하면 ED07 재개와 상호 대기하므로, 억제 중에는 SDK 준비·최신 모터 위치 등으로 시작을 확인하고 실제 취득은 ED07 재개 이후 시작합니다. GUI 구동 명령의 Success는 접수 의미입니다. 아래 GUI 구동 순서의 최신 구현은 DE07 재개 확인 후 isOperating을 활성화합니다.

## GUI 구동 순서 (2026-11-13)

### RDR 펌웨어가 제공해야 할 시작 전 상태

GUI 시작 요청을 받기 전에 ECS는 최신 RDR 제어 응답의 상태 플래그(24바이트 패킷의 오프셋 20)를 검사한다. FCS 미연결이어도 이 검사는 생략하지 않는다.

| 비트 | 의미 | RDR 구현 조건 |
| --- | --- | --- |
| 3 (`0x0008`) | ED07/DE07 방출 제어 지원 | 구현된 장비는 정지 상태에서도 지원 표시를 유지한다. 없으면 결과 15다. |
| 4 (`0x0010`) | 실제 방출 상태 유효 | 실제 ON/OFF를 확인한 경우 설정한다. 정지 중 실제 OFF가 확인되면 이 비트는 1이고 bit 5는 0이다. 없으면 결과 16이다. |
| 5 (`0x0020`) | 실제 방출 ON | 요청값이 아닌 실제 장비 상태를 보고한다. |
| 6 (`0x0040`) | 방출 억제 중 | 억제 상태에서도 ED06 준비 완료가 가능해야 한다. |

ED06 시작 완료만으로 GUI 구동 완료가 되지 않는다. ED07=1에 대한 DE07 완료 응답과 ACTIVE·보고 활성·지원·억제 해제가 확인되어야 한다. 실제 방출 상태 유효/ON은 구동 완료 조건이 아니다. 상태 유효 비트를 고정으로 1로 만드는 대신 실제 광원 상태를 확인해 보고해야 한다.

이전 동작 기록: 2026-11-13 실장비 확인에서는 RDR 연결은 정상이지만 GUI 명령 6이 결과 16(`lidar_unknown`)으로 거절되었다. 이는 FCS OFF 확인 이전의 RDR 상태 검사 실패이며, FCS 미연결 처리 변경으로 우회하지 않는다.

GUI 명령 6의 시작 요청은 다음 비동기 절차를 실행한다.

1. FCS가 연결되어 있으면 EF04 OFF 성공·현재 OFF 응답을 받고, 그 이후 최신 FE02에서 이동/시연/출력 종료·무오류를 확인한다(최대 10초). FCS 미연결 또는 RDR 단독 실행에서는 FCS OFF 명령과 확인을 생략한다. 이는 실제 FCS 출력이 OFF임을 확인했다는 의미가 아니다.
2. 보고가 꺼져 있으면 ED03 보고를 켠 후 ED06 시작을 요청하고 준비 완료를 기다린다(최대 45초).
3. FCS가 연결되어 있으면 최신 OFF 상태를 다시 확인하고 ED07=1을 전송한다. 이 시점에도 FCS가 미연결이면 FCS 상태 확인을 생략한다. 기존 억제 여부와 무관하게 매 시작 요청마다 전송한다.
4. DE07 OK와 지원·ACTIVE·보고 활성·억제 해제를 확인한 뒤 공유 메모리 isOperating을 활성화한다(재개 최대 6초, RDR 처리 제한 5초보다 여유 확보). PENDING은 대기하고 FAILED 또는 타임아웃은 실패한다.

명령 6 성공은 접수 의미이며 GUI는 명령 18로 완료를 조회한다. 결과 7은 진행 중, 0은 완료, 21은 준비 완료 후 방출 재개 확인 실패, 22는 FCS OFF 확인 실패, 23은 RDR 준비 실패다. 실패 시 isOperating은 비활성으로 유지되고 실패 사유를 표시한다. 정지 요청은 진행 중 시작 절차를 취소한다. RDR 펌웨어는 억제 상태에서도 ED06 준비 완료 응답을 보낼 수 있어야 한다.

이 절차는 GUI 구동 명령 6에 적용한다. 저수준 CLI `rdr start` 및 RDR 제어 파이프 명령 11은 기존 ED06 진단 명령으로 유지한다.

- 종료: `powershell -File scripts/stop-rdr-live-fcs-dummy.ps1` (GUI는 별도 종료)

- 로그/상태: `logs/rdr-live-fcs-dummy/`. 시작 스크립트는 기존 ECS가 실행 중이면 중복 실행을 거부한다.

## 상태 8 대응 (2026-11-15)

GUI 수동 조사 중지(1004)는 방출 상태 미확인(bit 4=0)이어도 ED07=0을 전송한다. 요청 허용과 출력 허용은 별개다. DE07 OK 이후에도 실제 OFF가 미확인이면 중지 완료 상태로 전환하지 않으며, FCS 출력도 차단한다. 6초 내 OFF 확인이 없으면 중지 확인 실패로 처리한다.

bit 4=0만으로 감시 시작/재개를 차단하지 않는다. DE07 재개 OK는 SDK 제어 완료이며 실제 광원 ON 확인이 아니다. GUI는 구동 완료 + bit 4=0일 때 `구동 중 / 방출 상태 미확인`으로 표시한다. IPC 명령 19는 ECS의 기존 RDR 상태를 조회하며 assignment=상태 유효, active=유효한 ON, connected=현재 연결이다. 별도 ED08/DE08 온도 조회는 제거했다.

FCS 출력은 정지 요청에 대한 DE07 OK와 bit 4=1, bit 5=0 및 기존 억제/최신 FCS 상태 조건을 모두 만족해야 한다. 미확인은 OFF가 아니다.


## 온도 경고와 보호 정지 (2026-11-15)

- 상태 7 WARN_TEMP: 경고 표시, 경고만으로 자동 정지하거나 작업을 보류하지 않는다.
- 상태 8 TEMP_DownFreq: 감속 운용 표시, 센서 내부 주파수 저하 보호를 유지한다.
- 상태 9 ERR_TEMPH: RDR이 억제와 FAULT를 래치하고 STOP을 요청한다. ECS는 FCS OFF를 요청하고 작업을 차단한다. 냉각만으로 자동 복구하지 않는다.
- 상태 7·8에서 실제 요청에 대응하는 신선한 SDK START/STOP 성공 응답과 내부 처리가 완료되면 RDR은 DE07 OK를 반환한다. TEST 응답, 중복 PENDING, 실패·타임아웃·오래된 응답은 완료 근거가 아니다.
- ECS는 신선한 상태 7·8 + 대응 STOP 성공 + 지원 + 억제로 작업을 진행한다. 광학 known/on 비트는 바꾸지 않으며 GUI에 방출 미확인을 유지한다. 명시적인 ON 피드백, 고온 오류, 미확인·만료된 온도 정보는 이 예외로 통과시키지 않는다.

### 상태 전달

ED08/DE08은 24바이트이며 세션·순번·ReplyTo를 검사한다. 요청 offset6/8/14~23은 모두 0.
성공 응답 offset6은 SDK 상태(0~255, 미확인 255), offset8 bit0은 근거 유효, bit1은 보호 정지 래치.
나머지 필드는 기존 제어 응답과 동일하다. 보호 래치는 일반 DE02/DE07 flags bit7에도 즉시 실려, 다음 ED08을 기다리다 고온 중단 사유를 놓치지 않는다. RDR은 현재 작업 세대에서 SDK 근거의 전체 나이가 500ms 미만일 때만 유효로 보낸다.
ECS는 1초마다 조회하고 2.5초 이후 정보 유효성을 해제한다. 보호 래치는 정보 만료만으로 해제하지 않으며 새 세션에서 초기화한다. ED08을 지원하지 않는 구버전은 미확인으로 표시하고 경고 예외를 허용하지 않는다.

GUI IPC 명령 20 응답: target_id=SDK 상태, assignment=유효(0/1), active=보호 래치(0/1), connected=RDR 연결.
기존 명령 19는 광학 상태 전용으로 유지한다. 492/40바이트 ABI는 변경하지 않는다.
결과 26=고온 보호 정지, 27=온도 경고가 동반된 중지 완료 확인 실패. 27은 실패 시점의 상태를 저장하며 경고가 모든 실패의 직접 원인이라고 단정하지 않는다.
실제 섭씨 온도나 위험 임계 온도를 추정하지 않는다.

## 촬영 후 객체 소실 결과 (2026-11-15)

운용 요청에 따라 수동 촬영의 결과 판정을 변경했다. FCS 촬영 동작 시작·종료를 확인하고 RDR 재개 후 3초 동안 대상이 다시 관측되지 않으면, 정상 연결·동일 세션·유효한 ON 상태·FCS 출력 종료 조건에서 HIT(108), 성공으로 완료한다. 기존 동일 ID 재관측은 ALIVE이며, ID가 바뀌어도 관측 자세를 보정한 촬영 기준 좌표의 0.15m 이내에서 새 실측 객체가 관측되면 ALIVE로 처리한다. 통신 단절, 상태 만료, 광원 미확인 및 장치 오류를 HIT로 바꾸지 않는다. HIT는 이 촬영 작업의 완료 판정이며 이미지 파일 저장을 검증한 의미는 아니다. 장치 명령과 자동 재개 동작은 변경하지 않는다.
