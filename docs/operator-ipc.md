# 외부 운영 화면 IPC v3 유지

GUI 소스와 계약은 변경하지 않습니다. ECS만 새 DE03를 수신해 기존 GUI 형식으로 변환합니다.

| 항목 | 규격 |
|---|---|
| SharedMemory | `Local\ControlStationMock.SharedMemory.v3` |
| Mutex | `Local\ControlStationMock.SharedMemory.Mutex.v3` |
| Frame magic / version | `0x314D4354` / 3 |
| Frame / header / payload | 492 / 32 / 460 bytes |
| RDR / FCS / target | 40 / 40 / 36 bytes, Pack=4 |
| Pipe | `ECS_NamedPipe`, magic `0x50495045`, version 3 |
| Request / response | 40 / 40 bytes |

모든 필드는 little endian이며 float32 및 기존 FNV-1a 체크섬을 유지합니다.

## 좌표와 표시

원본 센서 XYZ(오른쪽·위·앞), 관측 PAN/TILT, Detected, TrackState는 ECS 내부 및 `rdr targets` JSON에 보존합니다. GUI v3에는 이 필드들을 추가하지 않습니다.
관측 TILT, 북쪽 기준 PAN을 순서대로 적용하고 설치 위치를 더해 기존 GUI XYZ(동·북·위)를 만듭니다. 장착 회전 단위행렬·장착 이동량 0을 가정하며 실측 검증은 별도입니다.
GUI 목표 목록 XYZ는 RDR 기준 상대 좌표가 아닌 **월드 좌표(미터)**입니다. `월드 객체 = 관측 자세로 회전한 센서 객체 + RDR 월드 위치`를 적용합니다. 같은 ID의 원본 XYZ·관측 자세가 갱신되면 목록과 지도도 최신 월드 좌표로 갱신됩니다. GUI 게시 시 최초 좌표 저장값을 사용하지 않으며 별도 콘솔 명령이 필요하지 않습니다. FCS 객체 할당도 같은 최신 필터 좌표를 사용합니다.
PAN=1800은 북쪽입니다. RDR·FCS 장치 방향은 기존 GUI 방향선 계약의 135도 표시 오프셋을 유지합니다. 객체 목록의 방위각에는 이 오프셋을 적용하지 않으며 북쪽 0도·동쪽 +90도·서쪽 -90도 기준으로 전달합니다. RDR 방향은 기존 0~270도 범위로 제한하므로 범위 밖 방향은 기존 GUI에서 정확히 표시할 수 없습니다.
현재 RDR 자세와 객체 방향은 서로 다르며 객체 계산에는 해당 객체의 관측 자세를 사용합니다.
PREDICTED는 동일 ID와 좌표를 기존 유효 객체으로 전달합니다. 기존 GUI에는 별도 예측 라벨이 없습니다.
LOST와 자세 미상은 valid=0으로 전달하므로 기존 GUI 목록에서 숨겨집니다. ECS 내부 ID와 원본 정보의 보존과 GUI 표시 여부는 별개입니다.
ECS의 마지막 수신 이후 3초 통신 타임아웃과 송신측 마지막 관측 이후 최대 1.5초 예측 제한은 별개입니다. DE03에는 관측 시각이 없어 ECS가 실제 예측 경과 시간을 입증할 수 없습니다.
기존 GUI는 미상 각도 센티널을 처리하지 않으므로 현재 자세 미상일 때 기존 기본값(방위135/고각0)을 유지합니다.

## GUI 좌표 필터

GUI 목표 목록·지도에 전달하는 월드 XYZ에는 기본으로 ID별 3축 독립 칼만 필터를 적용합니다. 위치만 추정하는 랜덤워크 모델이며 속도 추정이나 미래 위치 외삽은 하지 않습니다. 월드 좌표 변환 후 필터를 적용하고, 표시 방위각·고각·거리도 같은 필터 좌표에서 계산합니다. `TargetPositionFilter`가 GUI와 FCS가 함께 사용할 최신 월드 좌표를 계산합니다. FCS 객체 할당은 같은 필터 결과에서 FCS 설치 위치를 뺀 상대 벡터를 사용합니다. GUI 전송 결과를 되읽거나 별도 저장하지 않으며 원본 센서 값은 보존합니다. 설정 키 `rdr.gui_kalman`은 기존 호환성을 위해 유지합니다. 좌표 변경으로 기존 정렬이 무효화되면 재할당해야 하며 자동 추종 명령은 보내지 않습니다.

실행 설정 JSON의 `rdr` 안에 아래 항목을 둡니다. 아래는 실측 기록으로 튜닝한 `configs/rdr-live.json`의 값입니다. 설정 변경은 ECS를 다시 실행하면 반영됩니다. 필터 설정 자체를 생략한 기존 환경의 기본값은 측정 0.05m, 과정 0.1m/√s, 적응 기능 꺼짐으로 유지합니다.

```json
"gui_kalman": {
  "enabled": true,
  "measurement_stddev_m": 0.03,
  "process_stddev_m_sqrt_s": 0.01,
  "adaptive_motion": true,
  "motion_process_stddev_m_sqrt_s": 0.08,
  "measurement_stddev_xyz_m": [0.025, 0.018, 0.005],
  "process_stddev_xyz_m_sqrt_s": [0.0075, 0.0054, 0.0012],
  "motion_process_stddev_xyz_m_sqrt_s": [0.06666667, 0.048, 0.01333333],
  "motion_trigger_sigma": 2.5
}
```

- `measurement_stddev_xyz_m`: 월드 X(동), Y(북), Z(위)별 측정 잡음 표준편차(m). 2분 정지 기록의 앞 60초에서 소실·재인식 구간을 나누고 각 구간 첫 2초를 제외했습니다. 실제 관측의 축별 표준편차 1.93/1.43/0.36cm에 25% 여유를 두고 1mm 단위 올림(최소 3mm)하여 2.5/1.8/0.5cm로 설정했습니다. 이는 절대 위치 오차가 아닙니다.
- `process_stddev_xyz_m_sqrt_s`, `motion_process_stddev_xyz_m_sqrt_s`: 축별 평상시·이동 시 과정 잡음(m/√s). 각 축의 분산과 이득을 따로 갱신합니다. 배열이 있으면 해당 스칼라 설정보다 우선하며, 배열을 생략하면 기존처럼 스칼라를 세 축에 동일하게 적용합니다.
- `measurement_stddev_m`: 축별 배열이 없는 환경의 측정 잡음 표준편차(m).
- `process_stddev_m_sqrt_s`: 시간에 따른 위치 변화의 불확실성(m/√s). 크게 설정할수록 새 측정을 빠르게 반영합니다.
- `enabled: false`: 필터를 거치지 않은 최신 월드 좌표를 표시합니다.
- `adaptive_motion`: 정지 시에는 작은 Q를 사용하고, 실제 관측으로 큰 위치 변화가 확인되면 일시적으로 Q를 높입니다.
- `motion_process_stddev_m_sqrt_s`: 이동 확인 시 사용하는 과정 잡음 표준편차(m/√s). 평상시 과정보다 작게 설정할 수 없습니다.
- `motion_trigger_sigma`: 각 축의 잔차를 해당 축의 `sqrt(P_prior + R)`로 나눈 벡터의 길이 문턱입니다. 다음 OBSERVED가 3초 안에 들어와 정규화한 잔차 방향 차이 60도 미만, 크기 절반 문턱 초과이면 이동으로 확인합니다. 확인한 관측과 이후 실제 관측 2회에는 이동 Q를 적용합니다. 단일 튐, 중복 표시, PREDICTED 자체로 이동을 확인하지 않습니다.

각 축 i의 측정 분산은 `R_i=measurement_stddev_xyz_m[i]²`, 새 관측 사이의 과정 분산은 `Q_i=process_stddev_xyz_m_sqrt_s[i]² × dt`입니다. 이동 확인 시에는 해당 축의 이동 과정 잡음으로 바꿉니다. 축 사이 공분산은 0으로 가정합니다. [Welch·Bishop의 칼만 필터 설명](https://www.cs.unc.edu/~welch/media/pdf/kalman_intro.pdf)을 참고했습니다.

적응 기능은 위치 랜덤워크 필터에 이동 확인 규칙을 추가한 좌표 보정입니다. [MathWorks의 잡음 튜닝 설명](https://www.mathworks.com/help/fusion/ug/tuning-kalman-filter-to-improve-state-estimation.html)처럼 정지 안정성과 이동 반응을 함께 평가했습니다. 1Hz 합성 계단 입력에서 10/20cm 변화의 90% 반영에는 모든 축에서 2회, 5cm 변화에는 X/Y 8회·Z 2회 관측이 필요했습니다. 이 이동 결과는 실장비 이동 시험이 아닙니다. `--status-file` 출력의 `gui_kalman`에서 실제 실행 설정을 확인할 수 있습니다.

`dt`는 로컬 DE03 수신 시각 차이입니다. 패킷에 센서 측정 시각이 없으므로 센서 자체의 관측 간격과는 다를 수 있습니다. 같은 수신값을 GUI 프레임·콘솔 조회가 다시 읽어도 중복 갱신하지 않습니다. 첫 관측은 즉시 표시합니다. 소실·제외·자세 미상·ID 제거·연결 세션 변경·감시/보고 중지·RDR 설치 위치 변경·3초 초과 수신 공백·수신 시각 역행 시 필터 상태를 초기화합니다.

`OBSERVED`와 `PREDICTED` 모두 같은 ID의 표시 필터를 거칩니다. `PREDICTED`는 이전 표시 위치에서 예측 좌표 쪽으로 부드럽게 보정하되, 오차 분산은 시간 경과에 따른 증가만 반영하고 측정 갱신에 따른 감소는 적용하지 않습니다. 송신측 예측은 기존 관측과 관련되어 있으므로 독립 측정으로 취급하지 않는 보수적인 표시 보정입니다. OBSERVED가 다시 들어오면 표시 상태를 이어서 일반 칼만 갱신을 수행합니다. 첫 유효값은 즉시 표시하고 이후부터 보정하며, 같은 수신값의 중복 처리 방지와 소실·타임아웃 시 초기화는 두 상태에 동일하게 적용합니다. 필터가 예측 유효 시간을 연장하지는 않습니다.

`rdr live on`의 `world_xyz`는 필터 전 비교용 좌표이고, `rdr targets`의 `gui_xyz`는 GUI에 전달할 필터 결과입니다. 합성 잡음 시험은 흔들림 감소와 위치 변화 수렴을 검증하며 실제 센서의 오차 보정·잡음 크기를 입증하지는 않습니다.

## 파이프 요청

EF05 용도에 대한 사용자 확인 (2026-11-08): `Active`가 요청하는 EF05는 촬영 시작이며, 레이저는 촬영 중인 객체 표시용입니다. 이는 사용자 확인에 따른 용어 설명이며 IPC 계약이나 실제 촬영 완료 판정을 변경하지 않습니다. [용어 정정](laser-control.md#용어-정정-2026-11-08)을 참고하세요.

공통 offset: magic@0, version@4, command@8, requestId@12, rdrId@16, fcsId@20, targetId@24는 uint32입니다.
positionX@28, positionY@32, positionZ@36은 float(m)입니다. 응답은 requestId와 command를 보존합니다.

| 번호 | 명령 | 값과 처리 |
|---|---|---|
| 0 | GetStatus | 현재 상태 조회 |
| 1~3 | Assign / Cancel / Active | 기존 계약 유지. 감시 정지 시 할당 불가 |
| 4 | SetRdrElevation | targetId=0~900, 0.1도 단위. 현재 ED/DE 보드는 명령이 없어 NotSupported |
| 5 | SetAssetPosition | RDR: rdrId=1/fcsId=0, FCS: rdrId=0/fcsId=1. 유한한 XYZ 필요 |
| 6 | SetRdrOperating | rdrId=fcsId=1, targetId=0 정지/1 구동 |

`Active`는 명칭 변경이며 명령 번호 3과 EF05 요청 동작은 유지합니다. 응답의 `active` 필드는 기존과 동일한 offset 32의 uint32이며, 값의 의미와 응답 크기 40바이트도 유지합니다. 이름 문자열은 전송하지 않으므로 기존 GUI 바이너리와 통신할 수 있습니다. 별도 GUI의 화면 문구는 해당 저장소에서 변경해야 하며, C++ 헤더를 직접 참조하는 외부 소스는 변경된 멤버명에 맞춰 수정해야 합니다.

위치 설정은 ECS가 실행 시 지정한 `--config` JSON의 `installation` 항목에 저장하고 재시작 시 복원합니다.
`--config` 없이 실행하면 실행 파일 옆 `installation.json`을 사용합니다. 위치 항목이 없으면 두 장치 모두 원점에서 시작하며 첫 적용 시 생성합니다.
저장 형식은 기존 `InstallationConfig`의 `observer`, `effector`, `devices` 구조입니다. 다른 설정과 장치 메타데이터는 보존합니다.
완성된 임시 파일로 원본을 교체한 뒤 Success를 응답합니다. 저장 실패 시 오류를 응답하고 기존 파일과 현재 위치를 유지합니다.
후속 프레임과 FCS 할당 계산에도 함께 반영하며, 실행 중 파일의 위치 항목을 수정하면 다시 읽습니다. 네트워크 설정 변경은 재시작이 필요합니다.
GUI 좌표는 내부 설치 좌표 (forward,left,up)=(GUI Y,-GUI X,GUI Z)로 변환합니다.
객체의 공통 좌표는 RDR 위치 + RDR 기준 측정값이며, 여기서 FCS 위치를 빼서 FCS 기준 벡터를 구합니다.
회전축/장착 방향 보정은 포함하지 않습니다.

위치를 바꾸면 기존 할당의 정렬 판정을 무효화하고 재할당을 기다립니다. 자동으로 다시 지향하지 않습니다.
동일 좌표 재적용은 기존 할당을 유지합니다. 계산 결과는 0.1도 단위로 전송하며 ECS의 자산별 팬·틸트 구동 한계 검사는 없습니다. 장비가 거부하면 장비 거부 결과를 전달합니다.
GUI 객체 목록의 각도는 RDR 기준, FCS 패널의 각도는 FCS 기준이므로 장비 위치가 다르면 두 숫자는 달라질 수 있습니다.

구동 요청은 ED03 보고 허용 후 DE02에서 reporting=1을 확인하고 ED06 시작을 보냅니다.
Success 응답은 요청 접수이며 실제 구동 완료는 후속 프레임의 isOperating으로 확인합니다.
정지 요청은 ED06 정지를 보내고 진행 중인 GUI 시작 단계를 취소합니다. CLI 정지도 GUI 시작 단계를 취소합니다.
통신 재연결만으로 감시를 자동 재개하지 않습니다. CLI `rdr` 명령과 확장 명령10~17은 유지합니다.

객체 할당은 RDR 감시·보고, FCS 연결·상태와 객체 유효성을 검사한 뒤 처리합니다.
할당 후 위치 변경 판정은 할당 당시 필터 좌표를 기준으로 합니다. 각 축 허용 오차는 `max(0.05m, 3 × 해당 축 measurement_stddev)`이며, 어느 축이든 범위를 벗어난 좌표가 새 DE03 수신 3회 연속 확인될 때 `target_changed`로 정렬을 무효화합니다. 같은 수신값의 반복 조회는 횟수에 포함하지 않고, 허용 범위로 돌아오면 연속 횟수를 초기화합니다. 비교 기준은 재할당 전까지 이동하지 않으므로 누적 이동도 감지합니다. 이 판정은 필터 좌표나 GUI 표시값을 수정하지 않습니다. 소실·연결 이상·장치 결함·세션/설치 위치 변경 검사는 유지하며, 자동 재지향은 하지 않습니다.

GUI 고각 설정은 정의되지 않은 보드 명령을 임의로 생성하지 않습니다.
