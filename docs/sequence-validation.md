# 카메라 수동 단계 연동 검증 — 2026-11-14

기준: ECS main cd1e474, GUI main 030c3b0. RDR/FCS 메시지와 GUI v3 패킷 크기를 유지한다.

## 빌드와 회귀 시험

- Release MSBuild 성공.
- `scripts/test.ps1 -Configuration Release` 전체 회귀 시험 성공: ICD 단위 시험, 수동 단계 6개 시나리오, 관측 보존, 라이다 연동, 카메라 설정, 설치 위치 저장, 좌표 기록·필터·분석, UDP/IPC 연동, 시뮬레이터 및 외부 모의 FCS.
- 이후 재시도 상태 초기화와 종료 직후 재개 조건을 수정했다. 최종 바이너리에서 ICD 단위 시험과 수동 단계 7개 시나리오를 다시 실행하여 모두 통과했다.
- `git diff --check` 성공.

수동 시나리오: 정상, 취소, 조사 상태 미확인, 정지 응답 누락, 객체 미검출, 새 ID, 5개 객체 순차 처리. 중복 촬영 요청이 중복 장치 실행으로 이어지지 않는지, 종료 후 명시적 재개를 기다리는지, 기존 제어로 단계를 우회할 수 없는지 확인한다.

## 발견 및 수정

1. 기존 라우팅이 1001 이상을 RDR 제어 요청으로 잘못 전달하여 GUI 단계 명령을 처리하지 못했다. 전용 ECS 단계 처리로 분리했다.
2. 재시도 시 이전 결과 관측 시작 여부가 남았다. 새 수행에서 초기화한다.
3. 상태 106을 표시한 직후 1007이 오면 다음 FE02를 불필요하게 요구하여 22를 반환했다. 진행 이후의 OFF를 확인하여 이미 106에 진입했다는 조건을 활용한다. 최신 상태 검사와 OFF 조건은 유지한다.
4. Windows 모의 장치의 스케줄링 지연이 제품의 80ms 응답 기한에 영향을 주었다. 수동 시험 프로세스에서 타이머 정밀도를 요청하고 종료 시 원복한다. 제품 통신 기한은 완화하지 않는다.

## 범위와 제한

모든 통합 시험은 localhost 모의 장치와 Windows Named Pipe/SharedMemory를 사용한다. 실제 RDR/FCS 펌웨어나 사진 파일 저장·품질은 검증하지 않았다. 운영 중인 사용자 ECS/GUI 프로세스를 교체하지 않았다.

FE02는 장치 진행·종료를 나타내며 이미지 저장 성공을 나타내지 않는다. 객체 미검출을 성공으로 처리하지 않고, 현재 GUI에 판정 불가 전용 상태가 없어 3 Failed와 원인 로그를 사용한다. 108 수동 결과 기록은 운용자가 촬영 결과를 별도로 확인한 경우에만 사용한다.
