# 거리·방향을 반영하는 FCS 3D 캘리브레이션

## 사용 순서

1. 메인 화면에서 라이다를 구동한 뒤 **카메라 방향 맞추기 · 방향키 조절**을 연다. 기존 객체 할당은 해제한다.
2. 이전 측정을 이어가려면 **상세 보기 → 저장한 작업 이어하기**부터 누른다. 설치 위치가 같으면 기존 v1 지점 파일도 사용할 수 있다.
3. 움직이지 않는 객체를 고르고 **이 객체 맞추기**를 누른다. 실제 카메라 영상에서 라이다가 가리킨 것과 같은 물리적 기준점을 맞춘다.
4. **방향키 조절 켜기** 후 ↑↓←→ 또는 화면 화살표로 조절한다. 이동 단위는 0.1°/0.5°/1°/5°/10°/30°이다. 각도를 바꿔도 조절 모드는 유지된다. 목록이 열려 있는 동안 방향키는 목록 선택에만 사용한다.
5. 중심에 맞춘 뒤 **중심에 맞췄어요 · 저장**을 누른다. 가까운 곳·중간·먼 곳, 좌우·높이가 다른 지점을 최소 12개, 가능하면 20~30개 모은다.
6. **다음: 다른 객체로 정확도 확인**을 누르고 계산에 쓰지 않은 위치를 최소 6개 모은다. 확인 지점도 가까운 곳·중간·먼 곳에 분포시킨다.
7. 검증 기준을 통과하면 결과와 수집 범위를 보고 **이 보정값 사용하기**를 누른다. 적용만으로 모터는 움직이지 않는다. 다음 객체 방향 지정부터 사용한다.

이 창에는 카메라 영상 스트림이 없다. 3D 뷰의 드래그/휠은 시점 회전/확대만 수행한다. 모터는 한 번 누를 때 한 번 움직이고 도착 상태를 받은 뒤 다음 명령을 받는다. 키 자동 반복이나 이동 명령 누적은 없다. Esc/창 전환은 추가 입력을 끄지만 이미 수락된 이동을 정지시키지는 않는다. 0.1°는 통신 명령 최소 단위로, 엔코더 1틱과 다르다.

## 새 계산 방식과 기존 숫자 입력란

기존 좌표→각도 공식은 유지하며 그 앞에 6자유도 강체 변환을 적용한다.

```
p = 객체의 월드 XYZ - 설정된 FCS 설치 위치
q = Rodrigues(rotation_rad) * p + translation_m
PAN  = 180° + atan2(q.east, q.north) + 기존 팬 미세 조정
TILT = atan2(q.up, hypot(q.east, q.north)) + 기존 틸트 미세 조정
```

translation_m은 변환 후 좌표계에서 더하는 값이며 물리적 장치 위치 그 자체가 아니다. rotation_rad는 Rodrigues 회전 벡터이다. GUI와 ECS 모두 east/north/up 순서를 사용한다. 설치 설정 파일의 기존 forward/left/up 변환은 기존 경로에서 처리한다.

팬·틸트 고정 평균 하나 대신 위치·회전 변환을 추정하므로, 같은 방향이라도 거리가 다른 객체에 서로 다른 보정 각도가 계산될 수 있다. 기존 **FCS 각도 보정** 숫자 입력란은 덮어쓰지 않는다. 그 값은 마지막 미세 조정으로 한 번만 더한다. 이후 이 숫자를 바꾸면 최종 방향도 바뀌므로 다시 검증해야 한다.

수동 정렬의 실제 각도에서 현재 미세 조정값을 제외해 단위 방향 벡터를 만든다. 이동을 중간 거리로 정규화한 뒤, 여러 초기값의 감쇠 비선형 최소제곱으로 방향 벡터 차이를 최소화한다. 확인 지점은 추정에 쓰지 않는다. 결과 오차는 두 방향 사이의 구면각을 도 단위로 계산한 RMS이며 픽셀 오차가 아니다.

방식 배경: [OpenCV PnP 공식 문서](https://docs.opencv.org/4.11.0/d5/d1f/calib3d_solvePnP.html)의 회전·이동 추정 문제와 유사하다. 이 구현은 OpenCV를 호출하지 않고 팬틸트의 단위 방향 벡터를 직접 사용한다.

## 수집 품질과 적용 조건

- 학습 지점은 서로 5cm 이상 떨어진 위치 12개 이상.
- 학습 거리 차이 0.5m 이상, 최대/최소 거리 비율 1.5배 이상.
- 학습 거리 범위를 3등분했을 때 각 구간에 2개 이상.
- 좌우 방향 분포 20° 이상, 높이 방향 분포 8° 이상.
- 변환의 수치적 조건이 나쁘거나 일직선 배치 등으로 위치·방향을 구분하기 어려우면 거절.
- 학습 지점과 떨어진 독립 확인 지점 6개 이상. 확인 지점도 3개 거리 구간에 분포.
- 학습/확인 RMS 각각 1° 이하, 각 지점 최대 오차 2° 이하. 확인 RMS가 기존 미세 조정만 사용한 결과보다 0.1° 넘게 악화되면 거절.

화면에는 수집/확인 거리 범위, 좌우·높이 분포, 보정 전후 확인 오차를 표시한다. 상세 표에는 지점별 3D 오차를 표시해 잘못 맞춘 지점을 찾을 수 있다. 기준 선택 후 5분 경과, 객체 이동 5cm 또는 0.2° 초과, 연결/관측 상실 시 측정 저장을 거절한다.

**모든 거리에서의 정확도를 보장하지 않는다.** 수집 범위 밖에서도 계산은 가능하지만 그 범위의 정확도는 별도 검증해야 한다. 라이다 좌표계 자체의 오차, 움직이는 객체, 서로 다른 기준점을 맞춘 경우, 모터 유격이나 회전 자세에 따라 달라지는 광축 편심은 이 고정 강체 모델로 완전히 설명되지 않을 수 있다.

## 저장·복원

- 지점: `%LOCALAPPDATA%/AadcCommandCenter/calibration-session.json` (v2). UTC 시각, 월드 좌표, 기준/실제 각도, 학습·확인 구분, 설치 위치, 시작 미세 조정 및 3D 모델을 보존한다. 교체 전 파일은 `.bak`으로 남긴다. 작업을 이어갈 때는 새 지점 저장 전에 불러온다.
- 적용 이력: 같은 폴더의 `calibration-models/날짜-고유번호.json`. 적용에 사용한 전체 지점, 모델, 범위, 오차, 기존 모델/미세 조정값을 별도 보관한다. 요청 전 Prepared로 기록하고 ECS 성공 응답 후 Applied로 갱신한다. Prepared만 있으면 적용 여부는 확정할 수 없다.
- 실제 적용 모델: ECS 설정 파일의 `installation.camera.fcs_geometry`. rotation_rad, translation_m, 활성 여부와 설치 위치 기준값을 저장한다. 재시작 후 유지한다.
- **시작 전 3D 보정으로 복원**: 현재 창을 열기 전 모델로 되돌린다. **3D 보정 끄기**: 기존 공식+미세 조정만 사용한다.
- 설치 위치를 변경하면 기존 3D 모델은 비활성화된다. 물리적으로 재설치했지만 설정 숫자를 바꾸지 않았다면 프로그램이 이를 알 수 없으므로 직접 새로 캘리브레이션해야 한다.

## IPC v3

기존 40바이트 ABI를 유지한다. GUI IPC, RDR/FCS ID=1에서만 허용한다.

| 명령 | 요청/결과 |
|---|---|
| 1100 | X=절대 PAN, Y=절대 TILT, Z=0, target=0. 각 축 변화 최대 30°, TILT [-30,90], PAN [0,360). EF03만 전송. |
| 1101 | target=객체 ID. 보정 전 공식 PAN/TILT를 응답 fcs_id/target_id의 float 비트로 반환. |
| 1102 | target=0. 실제 모터 PAN/TILT를 같은 방식으로 반환. |
| 1110 | target=0이 아닌 세션 토큰. 설정 스냅샷을 잡고 translation 3개를 응답 fcs_id/target_id/assignment float 비트로 반환. active=모델 활성. |
| 1111 | 같은 토큰으로 스냅샷의 rotation 3개를 반환. |
| 1112 | 같은 토큰, XYZ=translation. 새 임시 트랜잭션 시작. |
| 1113 | 같은 토큰, XYZ=rotation. 임시 값 완성. |
| 1114 | 같은 토큰, X=활성 0/1, Y=Z=0. 두 값이 완성된 경우 한 번에 저장. |

단계별 임시 값은 바로 적용하지 않으며 시작 후 30초 안에 커밋해야 한다. 설정 스냅샷 이후 설치 위치·미세 조정·3D 모델이 바뀌면 저장을 거절한다. 디스크의 최신 설정을 병합하고 파일 교체 성공 후에만 런타임을 갱신한다. 할당/동작 중 모델 저장은 거절한다. 일반/수동 방향 지정 양쪽에서 같은 변환을 사용하며 모델 변경 시 기존 정렬은 무효화한다. 캘리브레이션은 EF04/EF05를 호출하지 않는다.

## 검증과 빌드

GUI 빌드 구성은 `Calibration3D`, ECS 검토 빌드는 `build/calibration-3d/C2.Console.exe`이다. GUI/ECS를 함께 업데이트해야 한다.

- `dotnet run --project camera-calibration-check/CalibrationChecks.csproj -c Calibration3D` (c2 폴더): 수치 모델, 독립 거리 검증, 불충분/일직선 배치 거절, 기존 방향키 동작, 미세 조정 보존 및 적용 이력, WPF 렌더링.
- `C2.Tests/Integration/test_geometry_calibration.py --console ...`: C#에서 구한 모델의 C++ 일반/수동 경로, 여러 거리, 원자적 저장, 잘못된/오래된 트랜잭션, 재시작, 모델 해제와 설치 변경.
- 기존 `test_angle_calibration.py`, `test_calibration_mode.py`, C++ 단위 시험.

모의 27개 학습/6개 확인 지점에서 0.1° 양자화 조건의 확인 RMS는 약 0.05°였다. 이는 생성한 데이터의 시험 결과이며 실장비 성능 측정이 아니다. 실장비 정확도 검증은 사용자 수집 후 수행해야 한다.

### 확인 단계 자동 이동

확인용 객체를 선택하고 **보정된 각도로 이동**을 누르면 수집 지점으로 계산한 후보 모델의 각도로 이동합니다. 30° 이내 명령으로 나누고 매번 실제 도착을 확인합니다. 도착하면 0.1° 방향키 조절이 켜집니다. 맞으면 바로 저장하고, 다르면 미세 조정한 뒤 저장하세요. 확인 데이터는 모델 학습에 사용하지 않습니다. 후보 모델은 이 과정에서 ECS 설정에 적용되지 않습니다. Esc 또는 창 전환은 이후의 이동 명령을 취소하며 이미 전송된 이동을 되돌리지는 않습니다. 기존 지점 파일과 형식은 유지되고, 저장한 작업을 불러오면 확인 지점이 있는 경우 확인 단계로 이어집니다.
